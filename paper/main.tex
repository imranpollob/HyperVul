\begin{abstract}
Smart contracts manage billions of dollars of on-chain value and are immutable once
deployed, making automated vulnerability detection a critical safeguard. Existing
machine-learning detectors operate either at the function level or over pairwise
program graphs (AST, CFG, DFG, or call graphs). Both families decompose the
multi-entity interaction patterns that are the true locus of many vulnerabilities:
a reentrancy bug, for example, arises from the \emph{joint} presence of a function,
an accessed state variable, an external call, and a missing guard. Pairwise edges
fragment this $n$-ary relation into isolated binary signals. We propose \hypervul{},
which models each vulnerability-relevant interaction as a \emph{typed hyperedge} over
\{function, state variables, external callees, guard signals, cross-contract context\}
and classifies it without decomposition. \hypervul{} contributes (i) an
interaction-level hyperedge representation with an explicit construction algorithm,
(ii) security-aware symbolic feature augmentation, and (iii) interaction-level
localization of supporting evidence. Under a controlled three-question evaluation
across five random seeds, \hypervul{} outperforms seven generic baselines on F1, F2,
and PR-AUC; a representation ablation that holds the candidate interactions fixed
shows that the hyperedge encoding consistently beats set-pooling and pairwise GCN/GAT
reductions; and \hypervul{} reduces the false-positive rate on curated clean-contract
corpora from $19.3\%$ to $7.9\%$. A per-class breakdown localizes the advantage to
multi-entity vulnerability classes, a qualitative case study validates the
localization head, and gains are confirmed by paired McNemar tests and bootstrap
confidence intervals.
\end{abstract}

\section{Introduction}
%==============================================================

Smart contracts are self-executing programs deployed on blockchains such as Ethereum,
where they custody and transfer digital assets. Once deployed, their code is
effectively immutable, so a single latent vulnerability can be exploited
irreversibly. High-profile incidents---the DAO reentrancy attack, the Parity
multi-signature wallet freeze, and the Poly Network cross-chain exploit---have
collectively cost users hundreds of millions of dollars. Because patching a deployed
contract is often impossible, vulnerabilities must be caught before deployment,
which makes accurate automated detection a first-class security requirement.

Current detection tools fall into two families. \emph{Static analyzers} such as
Slither~\cite{feist2019slither} and Mythril~\cite{mueller2018mythril} apply
hand-written rules or symbolic execution; they are practical and interpretable but
suffer from high false-positive rates and miss vulnerabilities that depend on
complex, multi-entity interaction patterns. \emph{Machine-learning detectors} learn
from labeled code, but the overwhelming majority encode a contract either as a
function-level embedding or as a \emph{pairwise} program graph---an abstract syntax
tree, control-flow graph, data-flow graph, or call graph---in which every relation
is a binary edge between two entities.

This pairwise encoding is the central limitation we address. Consider the canonical
reentrancy pattern in Fig.~\ref{fig:motivation}: the vulnerability exists only because
the function \texttt{withdraw} \emph{jointly} (i) reads the state variable
\texttt{balances}, (ii) performs an external call before (iii) updating that state,
and (iv) is \emph{not} protected by a reentrancy guard. A pairwise graph represents
this as three separate binary edges (function--state, function--call, state--call)
and has no natural node for the \emph{absent} guard. The model must therefore
\emph{infer} the joint, four-way pattern from a collection of fragmentary binary
signals---precisely the information that decomposition discards.

We propose \hypervul{}, which preserves these higher-order interactions explicitly.
\hypervul{} models each vulnerability-relevant interaction as a \emph{hyperedge}: a
single classification unit containing a typed tuple of members---function, accessed
state variables, external callees, guard signals, and cross-contract context. A
hyperedge neural network consumes each interaction as one indivisible unit, so the
joint pattern is present in the forward pass rather than reconstructed from binary
edges. We further augment each hyperedge with security-aware symbolic features (guard
presence, reentrancy-protection flags, callee kind, cross-contract indicators) drawn
from lightweight static analysis, and we equip the model with a localization head
that attributes a prediction to the specific function--state--callee tuple
responsible.

\noindent\textbf{Contributions.}
\begin{itemize}
  \item \textbf{A typed hyperedge representation for smart contracts.} We define
  interaction hyperedges over \{function, state, callee, guard, cross-contract\} and
  give an explicit, linear-time construction algorithm
  (\S\ref{sec:arch}, Alg.~\ref{alg:construct}). The pipeline is isolated so that the
  generic baselines cannot inherit the representation.
  \item \textbf{A controlled three-question evaluation.} RQ1 compares against generic
  literature baselines that never see a hyperedge; RQ2 is a representation ablation
  that holds the candidate interactions fixed and varies only the encoding; RQ3 is a
  component ablation. Each question isolates a single variable.
  \item \textbf{Security-aware symbolic augmentation.} We show that static security
  features improve detection \emph{and} reduce clean-corpus false positives
  independently of the loss function.
  \item \textbf{Interaction-level localization.} \hypervul{} reports which
  function--state--callee tuple is the primary evidence for a prediction; we validate
  this both quantitatively (ablation) and qualitatively (a case study,
  \S\ref{sec:case}).
\end{itemize}

Across five seeds, \hypervul{} attains F1 $78.2$ and PR-AUC $82.7$, exceeding the
strongest non-hyperedge baseline by $+8.1$ F1, with all primary claims supported by
paired significance tests. The remainder of the paper reviews related work
(\S\ref{sec:related}), formalizes the task (\S\ref{sec:problem}), presents the
architecture (\S\ref{sec:arch}), describes the setup (\S\ref{sec:setup}), reports
results (\S\ref{sec:results}), presents a localization case study (\S\ref{sec:case}),
discusses threats to validity (\S\ref{sec:threats}) and implications
(\S\ref{sec:discussion}), and concludes (\S\ref{sec:conclusion}).

\section{Background and Related Work}
\label{sec:related}
%==============================================================

\subsection{Smart Contract Vulnerability Detection}
Static analyzers dominate practical deployment. Slither~\cite{feist2019slither}
performs data-flow and property checks over an intermediate representation;
Mythril~\cite{mueller2018mythril} and related symbolic-execution engines explore
reachable states to flag unsafe paths. Large-scale empirical
studies~\cite{durieux2020empirical} report that such tools achieve broad coverage but
modest precision and disagree substantially with one another. In our evaluation
Slither and Mythril reach only $41\%$ and $34\%$ precision respectively, and both
struggle with vulnerabilities defined by multi-entity context rather than local
syntactic patterns.

Learning-based detectors emerged to capture patterns that hand-written rules miss.
Early models embed a function or its bytecode and apply an MLP or a sequence model
over instruction streams~\cite{qian2020sequence}. A second wave casts detection as
graph learning over the AST, CFG, DFG, or call
graph~\cite{zhuang2020degree,liu2021combining}, optionally fusing expert patterns into
the graph. Across this literature the program is encoded with \emph{binary} edges or
function-level aggregates; the model never receives the full multi-entity interaction
as an atomic unit. Table~\ref{tab:positioning} positions these families against
\hypervul{} along five axes. \hypervul{} is distinguished by an interaction-level
unit, native higher-order edges, integrated security features, and built-in
localization.

\subsection{Graph and Hypergraph Neural Networks}
Graph convolutional networks~\cite{kipf2017gcn}, graph attention
networks~\cite{velickovic2018gat}, and relational GCNs~\cite{schlichtkrull2018rgcn}
propagate information along binary edges and form the backbone of graph-based code
models. Hypergraph neural networks~\cite{feng2019hgnn,yadati2019hypergcn} generalize
message passing to hyperedges connecting arbitrarily many nodes and have been applied
to social networks and bioinformatics. Crucially, these models operate on
\emph{generic, untyped} hyperedges defined by data-driven similarity or co-occurrence.
\hypervul{} instead constructs \emph{typed, semantically-grounded} hyperedges derived
from program analysis, where member roles (function, state, callee, guard,
cross-contract) carry distinct learned parameterizations and the hyperedge boundary
corresponds to a concrete program interaction.

\subsection{Interaction-Level Program Analysis}
Inter-procedural and demand-driven analyses reason over tuples of program entities
rather than isolated statements, and contrastive and pre-trained code
representations~\cite{guo2022unixcoder} have improved the quality of function-level
embeddings. \hypervul{} unifies these threads: it imports the multi-entity
perspective of program analysis into a neural setting, using pre-trained embeddings as
member features while letting a hyperedge encoder weigh higher-order evidence that a
binary-edge encoding cannot express directly.

\section{Problem Formulation}
\label{sec:problem}
%==============================================================

\noindent\textbf{Definition 1 (Interaction tuple).} A candidate interaction is a
tuple $I = (f, S, C, G, X)$, where $f$ is a function node, $S$ is a set of accessed
state-variable nodes, $C$ is a set of external callee nodes, $G$ is a guard-signal
vector of binary symbolic features, and $X$ is a cross-contract context indicator.

\noindent\textbf{Definition 2 (Hyperedge).} For a candidate interaction $I$, the
hyperedge $e_I$ is the set of its typed member nodes. Unlike a pairwise edge,
$|e_I| \ge 2$ and all members participate \emph{jointly} in a single relation. We
write $r(i)\in\{\textsc{fn},\textsc{st},\textsc{cl},\textsc{gd},\textsc{xc}\}$ for the
type of member $i$.

\noindent\textbf{Task.} Given a set of candidate interaction hyperedges
$\{e_1,\dots,e_N\}$ with binary labels $y_i \in \{0,1\}$ (where $1$ denotes a
vulnerable interaction), learn a classifier $h : e_i \mapsto [0,1]$ producing a
vulnerability score. This contrasts with function-level detection ($h: f \mapsto
[0,1]$) and contract-level detection ($h: \text{contract} \mapsto [0,1]$). The
interaction-level formulation is both more granular and directly localizable: a
positive prediction is already attached to a specific function--state--callee tuple.

\noindent\textbf{Class imbalance.} Vulnerable interactions are rare (positive rate
$\approx 6\%$, Table~\ref{tab:dataset}). We therefore report F1, F2, and PR-AUC;
accuracy is uninformative under this imbalance and is not reported.

\subsection{Hyperedge Construction}
\label{sec:construct}
Given a contract, \hypervul{} parses its source to recover function nodes,
state-variable nodes, and callee nodes, then enumerates candidate interactions by
linking each function to the state variables it accesses and the external calls it
issues. Alg.~\ref{alg:construct} details the procedure. Each function with an external
interaction surface (an external call or a security-relevant signature such as a
payable or privileged setter) yields one hyperedge; the guard vector $G$ and
cross-contract indicator $X$ are attached as typed member attributes. This pipeline is
\emph{isolated} in a dedicated module: the generic baselines of RQ1 are built by
separate view builders that never import it, so they cannot inherit the hyperedge
representation. The construction runs in a single pass over the program: for a
contract with functions $F$, the cost is
$O\!\big(\sum_{f\in F}(|S_f| + |C_f|)\big)$, i.e.\ linear in the number of
state accesses and calls, with no quadratic edge enumeration.

\begin{algorithm}[t]
\caption{Typed hyperedge construction for a contract}
\label{alg:construct}
\begin{algorithmic}[1]
\REQUIRE Contract $\mathcal{C}$ with functions $F$, state variables $V$, call sites
\ENSURE Set of typed interaction hyperedges $E$
\STATE $E \leftarrow \emptyset$
\FORALL{function $f \in F$}
  \STATE $S \leftarrow$ state variables in $V$ accessed by $f$
  \STATE $C \leftarrow$ external callees invoked by $f$
  \IF{$C = \emptyset$ \textbf{and} \textbf{not} \textsc{SecRelevant}($f$)}
     \STATE \textbf{continue} \hfill // no external interaction surface
  \ENDIF
  \STATE $G \leftarrow \textsc{ExtractGuards}(f)$
     \hfill // nonReentrant, CEI order, require-checks
  \STATE $X \leftarrow \textsc{CrossContract}(f, C)$
  \STATE $e \leftarrow \{\textsc{node}(f)\}
          \cup \{\textsc{node}(s): s\in S\}
          \cup \{\textsc{node}(c): c\in C\}$
  \STATE attach $G, X$ as typed attributes of $e$
  \STATE $E \leftarrow E \cup \{e\}$
\ENDFOR
\RETURN $E$
\end{algorithmic}
\end{algorithm}

\subsection{Typed Member Embeddings}
\label{sec:embed}
Each member is embedded according to its type. Function nodes use a pre-trained code
embedding (e.g., UniXcoder~\cite{guo2022unixcoder}) projected to dimension $d$.
State-variable nodes combine a type embedding with an access-pattern encoding
(read/write). Callee nodes combine an address-type embedding with an
external/internal flag. Guard signals are encoded as a fixed-length binary vector. The
result is a set of typed member vectors $\{m_1,\dots,m_k\}$, with each $m_i\in
\mathbb{R}^d$ tagged by its role $r(i)$.

\subsection{Hyperedge Encoder}
\label{sec:encoder}
The core encoder, \hyperedgenn{}, maps the member set of a hyperedge to a single
representation $z_e$ without decomposing it into pairwise edges. For each member role
$r$ we learn a query $q_r$; members attend to one another within the hyperedge via
role-aware attention:
\begin{equation}
\alpha_i = \frac{\exp\!\big(q_{r(i)}^{\top} W m_i\big)}
                {\sum_{j=1}^{k}\exp\!\big(q_{r(j)}^{\top} W m_j\big)},
\qquad
z_e = \sum_{i=1}^{k} \alpha_i\, W m_i ,
\label{eq:attn}
\end{equation}
where $W$ is a shared projection and the role-specific queries let the model weight
members differently by type (e.g., emphasize an external callee in the presence of an
unguarded state write). This contrasts with two reductions we evaluate in RQ2:
\emph{set pooling}, which mean-pools members and ignores structure entirely, and
\emph{pairwise GCN/GAT}, which clique-expands the hyperedge into binary edges and runs
message passing---reintroducing exactly the decomposition \hypervul{} avoids.

\subsection{Security-Aware Augmentation and Classification}
The hyperedge representation is concatenated with a security-context vector
$\phi_e$ before classification:
\begin{equation}
\hat{y}_e = \sigma\!\big(\mathrm{MLP}([\,z_e \,\Vert\, \phi_e\,])\big),
\label{eq:clf}
\end{equation}
where $\phi_e$ encodes guard presence, a reentrancy-protection (nonReentrant-like)
flag, callee kind (externally-owned account vs.\ contract), and a cross-contract call
indicator, all extracted by lightweight static checks during construction. This
augmentation is what distinguishes \textsc{HyperVul-Security} from
\textsc{HyperVul-EmbOnly} in the component ablation.

\subsection{Localization Head}
\label{sec:loc}
To attribute a positive prediction to specific members, \hypervul{} combines the
attention mass on each member with its prediction sensitivity:
\begin{equation}
a_i \;\propto\; \alpha_i \cdot
   \Big\lVert \frac{\partial \hat{y}_e}{\partial (W m_i)} \Big\rVert_2,
   \qquad \textstyle\sum_i a_i = 1 .
\label{eq:loc}
\end{equation}
The function--state--callee triple with the highest aggregate $a_i$ is reported as the
primary evidence. Removing this head (using $\alpha_i$ alone for both prediction and
attribution) defines \textsc{HyperVul-NoLocalize}; \S\ref{sec:case} shows the head
produces human-auditable evidence on real contracts.

\subsection{Training Objective}
\label{sec:train}
We train with class-weighted binary cross-entropy using
$\text{pos\_weight} = N_{\text{neg}} / N_{\text{pos}}$ to counter imbalance,
optionally combined with a supervised contrastive term~\cite{oord2018infonce} that
pulls hyperedge representations of the same label together within a mini-batch:
\begin{equation}
\mathcal{L}_{\text{con}} = -\frac{1}{|B|}\!\sum_{i\in B}
   \log \frac{\sum_{j: y_j=y_i, j\neq i}\exp(\mathrm{sim}(z_i,z_j)/\tau)}
             {\sum_{k\neq i}\exp(\mathrm{sim}(z_i,z_k)/\tau)},
\label{eq:con}
\end{equation}
with cosine similarity $\mathrm{sim}(\cdot,\cdot)$ and temperature $\tau$. The total
loss is $\mathcal{L} = \mathcal{L}_{\text{BCE}} + \lambda\,\mathcal{L}_{\text{con}}$;
setting $\lambda=0$ yields \textsc{HyperVul-NoContrastive}. Decision thresholds are
selected on the \emph{validation} set (Alg.~\ref{alg:thresh}) and applied once to the
test set. Every neural model is trained over five seeds ($42$--$46$); we report mean
$\pm$ standard deviation.

\begin{algorithm}[t]
\caption{Validation threshold selection (max-F2)}
\label{alg:thresh}
\begin{algorithmic}[1]
\REQUIRE Validation scores $\{p_i\}$, labels $\{y_i\}$, grid $\mathcal{T}$
\ENSURE Operating threshold $\tau^\star$
\STATE $\tau^\star \leftarrow 0.5,\; b \leftarrow -\infty$
\FORALL{$\tau \in \mathcal{T}$}
  \STATE $\hat{y}_i \leftarrow \mathbb{1}[p_i \geq \tau]$ for all $i$
  \STATE $F_2 \leftarrow \textsc{Fbeta}(\{\hat{y}_i\},\{y_i\}, \beta{=}2)$
  \IF{$F_2 > b$}
     \STATE $b \leftarrow F_2,\; \tau^\star \leftarrow \tau$
  \ENDIF
\ENDFOR
\RETURN $\tau^\star$
\end{algorithmic}
\end{algorithm}

\subsection{Baselines}
We organize baselines by research question.
\emph{RQ1 (generic baselines, no hyperedge):} Slither, Mythril, Function-MLP,

interactions and differ only in encoding.
\emph{RQ3 (component ablation):} \textsc{HyperVul-EmbOnly},
\textsc{HyperVul-Security}, \textsc{HyperVul-Full}, \textsc{HyperVul-NoLocalize}, and
\textsc{HyperVul-NoContrastive}.

\subsection{Evaluation Protocol}
We report Precision, Recall, F1, F2, PR-AUC, ROC-AUC, and false-positive rate on
clean corpora. Thresholds are chosen on validation (Alg.~\ref{alg:thresh}) and applied
once to test. Neural models run over five seeds; the static analyzers are
deterministic (single run). For primary claims we use paired McNemar
tests~\cite{dietterich1998} over test-set predictions and bootstrap confidence
intervals~\cite{efron1994bootstrap} for F1, F2, and PR-AUC.

shared hyperparameters; all comparable neural models use the same optimizer, schedule,
and imbalance handling so that differences reflect representation rather than tuning.

fires. Fig.~\ref{fig:loc} visualizes the localization attribution of

\noindent\textbf{True positive (reentrancy).} For the \texttt{withdraw} function of

concentrates attribution on three members: the external callee \texttt{msg.sender.call}
($a{=}0.41$), the state variable \texttt{balances} ($a{=}0.33$), and the
\emph{absent}-guard signal ($a{=}0.18$). The reported evidence tuple

head surfaces the actual root cause, not merely a salient token.

callee, but the guard signal carries low weight because a \texttt{nonReentrant}
modifier is present. This illustrates the residual FPR of Table~\ref{tab:fpr}: the
external-call surface alone is suggestive, and the model is appropriately less
confident once the guard feature is active. Such transparency lets an auditor dismiss
the alert quickly---an advantage of interaction-level localization over
contract-level scores.

\section{Threats to Validity}
\label{sec:threats}
%==============================================================

\noindent\textbf{Construct validity.} Labels for ``clean'' negatives assume the
absence of \emph{known} vulnerabilities; an unlabeled latent bug would be counted as a
false positive. We mitigate this by sourcing negatives from audited, widely-deployed
codebases and by reporting clean-corpus FPR separately
(Table~\ref{tab:fpr}). Hyperedge construction relies on static heuristics for
identifying state accesses and callees; missed accesses would omit members and weaken
the signal. The vulnerability taxonomy is finite and may not capture emerging classes.

\noindent\textbf{Internal validity.} To avoid attributing improvements to luck or
tuning, all neural models share seeds, splits, optimizer, and imbalance handling
(Table~\ref{tab:hparams}); thresholds are selected only on validation
(Alg.~\ref{alg:thresh}); and every comparison reports mean$\pm$std with paired
significance tests. The RQ2 design holds candidate interactions fixed so that only the
encoding varies.

\noindent\textbf{External validity.} Results are Solidity-only and drawn from the
described corpora; they may not transfer to closed-source enterprise contracts, other
smart-contract languages, or EVM bytecode without source. The dataset
($\sim$18.9K interactions) is modest by deep-learning standards. We therefore frame
claims as ``outperforms compared baselines under controlled evaluation'' rather than
universal state of the art.

%==============================================================
\section{Discussion}
\label{sec:discussion}
%==============================================================

\noindent\textbf{Why hyperedges help.} Reentrancy and access-control vulnerabilities
are inherently multi-party: their signature is a \emph{configuration} of several
entities rather than any single pairwise relation. A binary-edge model must
reconstruct this configuration from fragmentary signals, and the most diagnostic
element---an \emph{absent} guard---has no natural representation at all. By making the
interaction an atomic forward unit, \hypervul{} exposes the joint pattern directly.
The controlled RQ2 result isolates this as the source of the advantage, and the
per-class breakdown (Table~\ref{tab:perclass}) shows the gain concentrates exactly
where the multi-party hypothesis predicts.

\noindent\textbf{Practical implications.} The combination of a low clean-corpus FPR
and member-level localization addresses two recurring complaints about ML detectors:
alert fatigue and opacity. An auditor receives not just a score but the specific
function--state--callee tuple to inspect, with calibrated confidence.

\noindent\textbf{Future work.} Promising directions include protocol-level
cross-contract hyperedges, integration of dynamic execution traces, and operating
directly on EVM bytecode where source is unavailable.

%==============================================================
\section{Conclusion}
\label{sec:conclusion}
%==============================================================

We presented \hypervul{}, which detects smart-contract vulnerabilities by modeling
each vulnerability-relevant interaction as a typed hyperedge rather than decomposing
it into pairwise edges or function-level aggregates. \hypervul{} contributes an
interaction-level hyperedge representation with an explicit construction algorithm,
security-aware symbolic augmentation, and interaction-level localization. Under a
controlled three-question evaluation, \hypervul{} outperforms seven generic baselines
(F1 $78.2$, PR-AUC $82.7$), a representation ablation confirms that preserving
higher-order structure is the source of the gain, the advantage concentrates on
multi-entity vulnerability classes, and clean-corpus false positives fall from
$19.3\%$ to $7.9\%$. These results suggest that hyperedge representations are a broadly
useful primitive for program analysis whenever vulnerabilities arise from higher-order
interactions.
