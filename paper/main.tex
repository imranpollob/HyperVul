\begin{abstract}
Machine-learning detectors for smart-contract vulnerabilities routinely report
F1 scores above 85\% on balanced, duplication-prone datasets, yet remain
impractical on real audited code, where they over-flag benign contracts. We revisit
the problem at the level of \emph{interactions}---a function together with the state
it accesses and the external contracts it calls---modeled as a hyperedge over
\{function, state, callee\}. Through a controlled, multi-seed study we show that
whether relational structure helps at all is \emph{contingent on feature granularity}:
with rich full-text code embeddings every representation ties (structure is redundant),
but under an atomic, signature-hub representation a hypergraph significantly outperforms
pairwise-graph baselines ($p{=}0.0021$). We then attack the dominant failure mode---a high
out-of-distribution (OOD) false-positive rate on clean production code---and find that
\emph{safety-aware} atomic features (reentrancy guards, \texttt{SafeERC20} wrappers, checked
low-level returns), extracted from the AST, significantly reduce OOD false positives at
matched recall while improving detection, whereas a supervised-contrastive loss calibration
does not. On a hard, deduplicated test set where curated security rules reach at most 32 F1
and static analyzers cannot even compile the contracts, our model attains \mbox{64--66} F1.
We report our methodology---multi-seed evaluation, operating-point-controlled OOD
false-positive measurement, and an honest static-analyzer baseline---as a contribution in
its own right.
\end{abstract}

\section{Introduction}
% ----------------------------------------------------------------------------
Smart contracts are immutable, value-bearing programs; a single exploitable flaw can cost
millions. Automated vulnerability detection is therefore an active research area, spanning
static analyzers~\cite{slither,oyente,securify}, symbolic executors~\cite{mythril,manticore},
and a growing body of learning-based detectors~\cite{tmp,gnnscv,smartbugs}. Learning-based
methods frequently report very high accuracy, but these numbers are increasingly understood to
be inflated: popular benchmarks contain near-duplicate contracts and function-level label
leakage, and balanced splits do not reflect the operating regime of an auditor, who runs a
tool over mostly-benign production code~\cite{smartbugs,dappscan}. When evaluated on realistic,
deduplicated, contract-disjoint data, reported performance falls sharply, and the practical
bottleneck becomes \emph{false positives}: detectors that flag any external call drown auditors
in noise.

We argue that the right unit of analysis is not the token, statement, or whole function, but the
\emph{interaction}: a function together with the state variables it reads or writes and the
external callees it invokes. Reentrancy, transaction-ordering, and unchecked-call bugs are all
properties of how these elements are \emph{composed}, not of any element in isolation. We model
each interaction as a \emph{hyperedge} over the heterogeneous node set
$\{\text{function}, \text{state}, \text{callee}\}$ and study whether this representation detects
vulnerabilities better than pairwise-edge alternatives.

Our investigation produces three findings, each backed by a controlled, multi-seed experiment.
First, \emph{whether structure helps is contingent on feature granularity}. With full-text code
embeddings, the function node already textually encodes its calls and state, so a structure-free
set pooling ties every graph model. Only when features are made \emph{atomic}---the function
reduced to its signature, state and callee nodes to typed symbols---does structure become
essential, and in that regime the hypergraph significantly outperforms pairwise graphs on the
operating point and on cross-contract interactions.

Second, the dominant failure mode---OOD over-flagging---can be addressed with
\emph{features, not loss tricks}. Frozen code embeddings cannot see whether an external call is
guarded by a reentrancy lock or wrapped in \texttt{SafeERC20}. We extract these
\emph{safety-aware} signals directly from the AST and find they significantly reduce
OOD false positives at matched recall, and improve detection, across four clean codebases. A
supervised-contrastive calibration of the same model, by contrast, does not survive multi-seed
scrutiny---a negative result we report in full.

Third, on a deliberately hard, deduplicated test set, our model clearly beats the
\emph{runnable} baselines: curated security rules reach at most 32 F1, and off-the-shelf static
analyzers cannot be run at all because the audited contracts do not compile without their
(unbundled) dependency trees---itself a documented motivation for compile-free learned detection.

\noindent\textbf{Contributions.}
\begin{itemize}
\item An interaction-level hyperedge formulation of smart-contract vulnerability detection and a
``semantic bottleneck'' atomic feature schema extracted from the Solidity AST
(Section~\ref{sec:approach}).
\item A controlled representation study establishing that the benefit of relational structure is
contingent on feature granularity, with the hypergraph winning under atomic signature-hub
features ($p{=}0.0021$, Section~\ref{sec:rep}).
\item Safety-aware atomic features that significantly reduce OOD false positives at matched
recall and improve detection---outperforming loss-level contrastive calibration, which we report
as a negative result (Section~\ref{sec:safety}).
\item A rigorous evaluation protocol: multi-seed estimates, operating-point-controlled OOD
false-positive measurement, hard structural negatives, and an honest accounting of the
static-analyzer compilation gap (Sections~\ref{sec:setup}--\ref{sec:results}).
\end{itemize}

\section{Related Work}
% ----------------------------------------------------------------------------
\textbf{Static and symbolic analysis.}
Slither~\cite{slither}, Oyente~\cite{oyente}, Securify~\cite{securify}, and
Mythril~\cite{mythril} encode vulnerability patterns as hand-written rules or constraints. They
are precise on the patterns they target but require the contract to \emph{compile}, which for
audited real-world projects means resolving the full dependency tree (e.g., OpenZeppelin,
Uniswap). They also lack coverage for composition bugs such as transaction ordering.

\textbf{Learning-based detection.}
Sequence models over opcodes or source~\cite{smartbugs} and graph neural networks over
control-/data-flow graphs~\cite{tmp,gnnscv} have been applied to contract-level or function-level
labels. Reported scores are high but sensitive to dataset duplication and labeling
quality~\cite{dappscan}. We differ by (i) operating at the interaction level with an explicit
hyperedge, (ii) controlling feature granularity to isolate when structure helps, and (iii)
measuring OOD false positives on disjoint clean codebases.

\textbf{Hypergraph neural networks.}
Hypergraph convolution generalizes message passing to higher-order
relations~\cite{hgnn,hyperconv}. We use it as a faithful adjudicator against clique-expanded
pairwise graphs on an identical backbone.

\textbf{Representation learning and calibration.}
We use a frozen code encoder (SmartBERT~\cite{smartbert}) for node text and evaluate supervised
contrastive learning~\cite{supcon} as a calibration mechanism. Our finding---that explicit
safety features outperform contrastive calibration for OOD over-flagging---adds to the discussion
of features versus objectives for robustness.

\subsection{Interaction Extraction}
We parse Solidity with \texttt{tree-sitter} and, for each function $f$ in a (possibly inherited)
contract, build a hyperedge $h_f = \{f\} \cup S_f \cup C_f$, where $S_f$ are the state variables
$f$ accesses and $C_f$ are the external callees $f$ invokes. State accesses and external calls are
resolved over the inheritance hierarchy; external calls are classified by receiver type
(interface/contract/library), low-level call kind, and known ERC/DeFi method signatures.

\subsection{Semantic Bottleneck Feature Schema}
To control \emph{what} the model can exploit, we define an atomic schema that deliberately
discards function-body text:
\begin{itemize}
\item \emph{Function hub}: signature only---name, parameters, visibility, mutability, and
modifiers (no body). The hub is embedded by a frozen code encoder over the signature string.
\item \emph{State nodes}: typed symbols, split by access modality into \emph{read} and
\emph{write} (a variable read and written yields two nodes), each with a coarse type bucket.
\item \emph{Callee nodes}: the external target kind, the method invoked, and a
\emph{security context}---reentrancy-guard modifier, \texttt{SafeERC20} wrapper, low-level call,
and whether a low-level return is checked.
\end{itemize}
The schema is the ``bottleneck'' that forces the $\{f, S, C\}$ relation to be reassembled through
structure rather than read off from body text. Symbolic fields are encoded as fixed-width
categorical vectors and concatenated onto node embeddings.

\subsection{Models}
The deployed classifier pools the hyperedge member embeddings with a learned attention pool into a
single hyperedge vector, followed by a two-layer MLP:
\begin{equation}
\alpha_i = \mathrm{softmax}_i\big(v^\top \tanh(W x_i)\big),\quad
z = \textstyle\sum_i \alpha_i x_i,\quad \hat{y} = \sigma(\mathrm{MLP}(z)).
\end{equation}
For the representation study (Section~\ref{sec:rep}) we use a single unified backbone---
\textit{in-proj} $\rightarrow L\times$[conv $+$ residual $+$ LayerNorm] $\rightarrow$ attention
pool $\rightarrow$ MLP---in which only the convolution differs: GCN/GAT on the clique-expanded
pairwise graph, or hypergraph convolution on the incidence structure. Holding everything but the
operator fixed makes the comparison a fair adjudicator of \emph{structure}.

\subsection{Interaction Localization}
Beyond a binary verdict, an auditor needs to know \emph{which} interaction is responsible. We add a
localization head that scores every (function, state, callee) tuple by a factorized additive
attention,
$e_{jk} = w^\top \tanh(W_f f + W_s s_j + W_c c_k)$,
and pools the tuples into an interaction context that contributes to the logit, so the head is
trained by the binary objective (weakly supervised attribution). At inference it returns the
top-ranked responsible tuples. \todo{Quantitative faithfulness evaluation of localization is
ongoing (Section~\ref{sec:threats}); the current draft reports it as an architectural capability.}

\subsection{Safety-Aware Features and Calibration}
Two interventions target OOD over-flagging. (i) \emph{Safety-aware features}: we activate the
callee security-context symbols (reentrancy guard, \texttt{SafeERC20}, low-level, checked-return)
and target kind, so the model can distinguish a \emph{guarded} external call from a dangerous one.
(ii) \emph{Contrastive calibration} (ablation): a supervised contrastive loss on a normalized
projection of the pooled embedding, up-weighting clean interactions that contain external calls.
We compare both against a no-symbolic baseline.

\section{Experimental Setup}\label{sec:setup}
% ----------------------------------------------------------------------------
\textbf{Data.} We draw vulnerable interactions from FORGE and DAppSCAN~\cite{dappscan} audited
findings (SWC-107 reentrancy, SWC-114 transaction ordering, SWC-104 unchecked call), and
structurally matched clean negatives. Negatives are \emph{hard}: by construction every interaction
contains external calls and state access, so a trivial ``flag any external call'' detector is
uninformative. Splits are contract-disjoint. The held-out test set has 169 interactions
(44 vulnerable, 125 clean). \todo{Insert full dataset statistics table: \#projects, \#contracts,
\#interactions per split, SWC distribution, cross/intra ratio.}

\textbf{OOD clean holdouts.} To measure over-flagging on never-seen benign code, we evaluate
false-positive rate (FPR) on four clean codebases disjoint from training: an OpenZeppelin holdout
(63), MakerDAO~DSS (424), Bancor~V3 (209), and Liquity~V1 (279). All items are clean; FPR is the
fraction flagged.

\textbf{Metrics.} We report Precision, Recall, F1, F2, PR-AUC and ROC-AUC on the test set.
Because all holdout items are clean, FPR is purely threshold-driven; we therefore report OOD FPR at
a \emph{matched operating point}---the threshold that yields a fixed test recall (90\%)---so that
arms are compared at equal detection capability rather than at independently tuned thresholds. We
also report McNemar tests on per-item false-positive decisions.

\textbf{Protocol.} Node text is encoded by a frozen SmartBERT~\cite{smartbert} (768-d). Unless
noted, hidden size 256, dropout 0.3, Adam ($\mathrm{lr}{=}10^{-3}$), two layers; the decision
threshold is the highest achieving $\geq 95\%$ validation recall. Every result is reported over
\textbf{5 seeds} (42--46) as mean$\pm$std; representation experiments additionally report McNemar
significance. \todo{Confirm final hyperparameters and seed set in camera-ready.}

\textbf{Baselines.} (i) Rule-based detectors emulating the static-analyzer family over identical
features (e.g., unguarded-external-write, unchecked-low-level, non-\texttt{SafeERC20} transfer).
(ii) Within-backbone learned baselines (set pooling; pairwise GCN/GAT). (iii) Off-the-shelf static
analyzers could not be run: the audited contracts import unbundled \texttt{@openzeppelin}/
\texttt{@uniswap}/\texttt{node\_modules} dependencies and do not compile standalone---a
compilation-coverage gap we report rather than work around. \todo{Add a learned external baseline
(e.g., a re-implemented GNN detector) on this split for the camera-ready.}

\subsection{RQ1: Does structure help, and when?}\label{sec:rep}
Table~\ref{tab:rep} reports the unified-backbone comparison under three feature granularities.
With full-text function embeddings, all representations tie near 63 F1: the function node already
contains its calls and state textually, so \emph{structure is redundant}. Removing the function
node (atomic state$+$callee only) makes structure essential---set pooling collapses by $\sim$17 F1
while pairwise GCN recovers to 55.2---but here pairwise \emph{beats} the hypergraph
($p{=}0.0008$). The decisive regime is the \emph{signature hub}: when the function is kept but
reduced to its body-free signature, the hypergraph reaches 59.4 F1 and significantly outperforms
pairwise GCN ($p{=}0.0021$), including on cross-contract interactions where the multi-step relation
lives. Thus the benefit of relational structure is \emph{contingent on feature granularity}, and
the higher-order hyperedge is the right structure once the function is an atomic hub.

\subsection{RQ2: Can safety-aware features reduce OOD over-flagging?}\label{sec:safety}
We ablate the symbolic block in three architecture-matched arms: \emph{none} (zeroed symbolic),
\emph{security} (safety slots only), and \emph{full} (all symbolic). Because all arms share the
same input width, any difference is due to \emph{information}, not capacity.

Table~\ref{tab:fpr} reports OOD FPR at matched recall. Activating safety features substantially
lowers false positives \emph{and collapses seed variance} (e.g., Liquity $33.5\!\rightarrow\!16.5$;
MakerDAO $60.9\!\rightarrow\!45.8$; std roughly halved). McNemar confirms the effect is significant
on all four holdouts ($p<10^{-4}$; e.g., on MakerDAO the security arm fixes 177 false positives
while introducing 11). Detection improves in tandem (Table~\ref{tab:det}): F1
$64.2\!\rightarrow\!66.0$, PR-AUC $64.4\!\rightarrow\!69.6$, ROC-AUC $86.8\!\rightarrow\!88.6$, with
recall maintained. The \emph{security} arm---safety signals only---captures nearly all of the
benefit and is best on MakerDAO, making it our recommended, interpretable configuration.

In contrast, supervised-contrastive calibration of the same model did \emph{not} reduce OOD FPR
under multi-seed, matched-recall evaluation: an apparent single-seed improvement vanished once the
threshold confound was removed, and the calibrated model was neutral-to-worse on three of four
holdouts with \emph{increased} variance. We report this as a negative result: for OOD
over-flagging, \emph{explicit safety features outperform loss-level calibration}.

\section{Discussion and Threats to Validity}\label{sec:threats}
% ----------------------------------------------------------------------------
\textbf{What the numbers mean.} Absolute F1 in the mid-60s is modest against headline ML claims,
but those claims rest on easy, duplication-prone data; on a hard, deduplicated, hard-negative set
where rules reach $\leq 32$ F1 and static tools cannot run, mid-60s F1 reflects genuine difficulty.
Our contributions are the \emph{conditional} role of structure and the \emph{feature-based} OOD
fix, not a new state-of-the-art F1.

\textbf{Statistical power.} The test set has 44 vulnerable items; per-class and per-SWC numbers are
indicative. We mitigate this with 5-seed estimates, paired McNemar tests, and large clean-holdout
FPR measurements (209--424 items), but the detection F1 gains in RQ2 ($\pm 1\sigma$) require
benchmark-scale confirmation. \todo{Scale to the full FORGE/DAppSCAN benchmark.}

\textbf{Operating-point sensitivity.} We learned that comparing all-clean FPR at independently
tuned thresholds conflates model quality with threshold noise; the matched-recall protocol
(Section~\ref{sec:setup}) is essential and we recommend it for OOD false-positive studies.

\textbf{Label quality and construct validity.} Labels derive from audit findings; some are
imprecise at function granularity. \todo{Add a label-quality audit / inter-annotator note.}

\textbf{Localization.} The localization head is currently evaluated only as an architectural
capability; a faithfulness study (deletion/insertion of the top tuple; agreement with annotated
responsible nodes) is in progress.

\section{Conclusion}
% ----------------------------------------------------------------------------
We studied smart-contract vulnerability detection at the level of interactions and showed that the
value of relational structure is contingent on feature granularity: a hypergraph over
$\{$function, state, callee$\}$ significantly outperforms pairwise graphs only once features are
made atomic with a signature hub. Targeting the practical bottleneck of out-of-distribution
over-flagging, we found that safety-aware features extracted from the AST significantly reduce
false positives at matched recall and improve detection---outperforming loss-level contrastive
calibration. Beyond a verdict, the model localizes the responsible interaction. Future work scales
the study to a full benchmark, adds a learned external baseline, and quantitatively evaluates
localization faithfulness.
